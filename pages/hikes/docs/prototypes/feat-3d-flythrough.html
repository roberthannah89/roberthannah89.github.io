3D Flythrough

Cinematic MapLibre camera follows the GPX ascent — FATMAP-style preview, no API key, lazy-loaded behind the existing 3D button.

DONE

Demo

Open uri-rotstock.html — "3D Terrain View" → "Load interactive 3D view" → "Play flythrough"

Uri Rotstock (978→2921 m, 1943 m ascent) — most dramatic in the repo. Camera follows the GPX for ~45 s with eased motion + smoothed bearing, then pulls back 6 s at the summit. Pause/Resume/Replay supported. Ships on all 75 hikes via the shared asset.

Stack

  • MapLibre GL JS 4.7.1 — free, open source.
  • swisstopo SWISSIMAGE raster tiles draped over AWS Open Data Terrarium DEM (raster-dem encoding).
  • No API key, no Mapbox dependency. The existing hike_3d.js already used this stack — extended with a cinematic camera animation instead of swapping libraries.

What got built

  • "Play flythrough" button top-right of the 3D map (once the 3D view itself is loaded).
  • GPX trimmed to ascent-only via findSummitIndex (correctly handles loop hikes — uri-rotstock returns summit at index 1879 of 3997).
  • Track resampled to 450 even-spaced points; bearings pre-computed and smoothed for cinematic motion.
  • Per-frame work is O(1) interpolation + map.jumpTo. 60 fps desktop, 30+ mid-range phone (tile streaming is the real bottleneck).

Performance / bundle

  • MapLibre GL ~210 KB gzipped; CSS ~25 KB gzipped. Loaded lazily — only fetched after the user clicks "Load 3D view". Zero cost on first paint.
  • Flythrough adds ~13 KB unminified to hike_3d.js (~5 KB gzipped). Negligible.
  • Tile pop-in during the first ~5 s of mobile playback is the worst-looking artifact — could pre-warm via low-zoom fitBounds before play.

Files touched (in worktree)

  • templates/_assets/hike_3d.js — flythrough logic + helpers (with unit-tested bearing, bearingDelta, resample)
  • routes/_assets/hike_3d.js — mirrored by sync_assets
  • Regenerated routes/uri-rotstock/uri-rotstock.html + uri-rotstock.3d.html standalone fullscreen page

Recommended next steps if shipping

  1. Throttle on mobile — detect navigator.connection.saveData, drop to maxzoom: 14 or disable.
  2. Pre-warm tiles — fitBounds at lower zoom before play to populate the cache.
  3. Per-segment replay — "Replay this leg" anchors on individual route segments (climb only / descent only).
  4. No autoplay, no music. Obnoxious-by-default is a footgun.
  5. HUD elevation during playback for the "wow" reveal.
  6. Static MP4 capture via Playwright + ffmpeg for social-share images.

Verdict — ship it, conditionally

Pros: genuinely useful for route preview — answers "is this exposed? does it traverse a ridge?" far better than a contour map. Cost is near-zero (lazy-loaded, shared infra). Additive to the existing 3D button.

Cons: mild novelty if it's the only 3D interaction users encounter; satellite tiles look washed-out at low sun angles; mobile tile pop-in is ugly.

Verdict: ship behind the existing "Load 3D" gate (already lazy). Don't autoplay. Keep both the static topo map AND the 3D view — different questions. Predicted lift: 5–15% of 3D-loaders will play, >50% of those will share — meaningful for one afternoon's work, but only if it stays cheap. No per-hike POI annotations, no custom audio, no config — keep it as the auto-deriving feature it is.
