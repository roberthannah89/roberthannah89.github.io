Offline Cache (PWA)

Service worker + manifest so a hike loaded at home stays usable in the field with no signal.

DONE

Design memo

docs/design/offline.md

Covers scope, hosting, three tile-caching options (with a recommendation), cache budget (~10 MB/hike, ~55 MB realistic 5-hike user), graceful-degradation pattern for live data (weather, transport, webcams), and a 6-step phased rollout.

Recommended path

  1. GitHub Pages (already the target host) — required for any of the SW code to actually activate. Until then, everything no-ops safely on file://.
  2. Service Worker, cache-on-visit — static assets cached as the user browses; "Save for offline" button explicitly prewarms tiles+photos+GPX for one hike.
  3. "Open in swisstopo app" deep-link as the navigation escape hatch — deferred build-time tile precompute. Most hikers already have swisstopo installed.

What got built

  • manifest.webmanifest — PWA manifest, linked from index + hike pages, theme colour set, install-as-PWA-ready.
  • service-worker.js — cache-first for HTML/CSS/JS/photos/GPX, with explicit no-op on file://.
  • routes/_assets/sw-register.js — file://-safe registrar, computes SW path from its own script location.
  • "⤓ Save for offline" button on every hike — hidden until SW active, posts a PREWARM message that primes the cache with that hike's HTML/GPX/track/photos.
  • All 75 hikes + index re-rendered via make render.

Decisions you need to make

  1. Publish to GitHub Pages. None of the SW code activates until https://<your-org>.github.io/… is live. Likely just git push + flipping the Pages toggle.
  2. Tile-caching policy. Memo recommends cache-on-visit + swisstopo deep-link. Confirm, or push for build-time tile precompute (no pre-warm step needed, but big repo bloat).
  3. Asset budget per saved hike. Memo estimates ~10 MB (mostly tiles + ~3 MB SAC photos). OK, or tighten to thumbnails-only?

Once GitHub Pages is live, the next ticket is "self-host Leaflet under routes/_assets/vendor/" (memo §4) — removes the unpkg dependency, unlocks fully-offline first-load.
