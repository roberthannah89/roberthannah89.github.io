Hazard Markers

Pin chain sections, exposed ridges, stream crossings & other hazards along the route on individual hike pages.

Demo

Open hardergrat.html in worktree

Hardergrat T4 (Kemmeriboden → Brienzergrat → Harder Kulm). Chosen because SAC prose flags "exponiert", "luftige Grasgrate", "kaum Fehler verzeiht" — textbook scary-ridge hike.

What got built

  • 7 hazard pins sampled along the existing GPX so they sit on the route, not floating.
  • Hazard types: cable ⛓, exposed 🪂, scree 🪨, stream 💧, snow ❄, cableway 🚠, fallback other ⚠.
  • Stored as hazards[] in data.json with { type, lat, lon, note }.
  • Toolbar toggle "⚠ Hazards", on by default. Click a pin for a popup with the note.

Files touched (in worktree)

  • routes/hardergrat/hardergrat.data.json — hazards[] array
  • templates/hike_page.j2.html — passes hazards into window.HIKE, toolbar button
  • templates/_assets/hike_page.js — HAZARD_KINDS lookup, layer + toggle wiring
  • templates/_assets/hike_page.css — .hazard-marker + .hazard-popup

Data-source recommendation

Hybrid — pure regex on SAC prose is too noisy for a safety layer; hand-authoring every hike doesn't scale to ~75 hikes.

  1. Write scripts/suggest_hazards.py that scans intro_html + routes[].notes_html for keyword families (Kette/Drahtseil → cable, exponiert → exposed, Geröll → scree, Bach → stream, …) and emits a hazards-suggested.json — without coordinates, since SAC prose doesn't say where along the route.
  2. Human anchors each suggestion to a GPX point via a small click-on-map UI. Coordinates get added to data.json at curation time.
  3. Hikes without a hazards field just don't render the layer.

Open design questions

  • Severity / certainty — add a severity field (advisory vs. consequential), or stay flat? Affects whether icons colour-grade or filter.
  • Seasonality — snow gully in spring, stream impassable after storms. Add season / condition fields, or fold into the note text?
  • Linear hazards — chain sections and exposed ridges are stretches, not points. Allow optional [lat,lon] start+end (rendered as a coloured polyline overlay)?
  • Source attribution — if auto-suggest from SAC, expose source_quote in the popup so users can audit the call?
  • Mirror onto elevation profile — drop badges at the matching distance? Infrastructure for distance-along-track lookup already exists for waypoints.
