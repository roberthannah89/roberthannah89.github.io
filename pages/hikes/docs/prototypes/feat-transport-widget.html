Live Transport Widget

Next 3 outbound + last 3 return connections inline on every hike page — transport.opendata.ch, CORS-clean, file://-safe.

DONE

Demo

Open augstmatthorn.html, scroll to "Getting There" — live widget appears above the SBB button

Verified live: outbound rendered 3 real connections (IC 1 → RE 7 → B 251 to Kemmeriboden). Ships on all 75 hikes via the shared template.

What got built

  • Outbound column: next 3 still-bookable connections from the user's reference city to the trailhead today.
  • Return column: last 3 connections of the day from end_point back, dimmed if already departed.
  • Each row: departure time, platform, delay if any, mode badges (train/bus/cable/ship/tram), transfer count, arrival time, duration.
  • "From" station editable inline — change persists in localStorage.
  • On API/CORS failure: widget logs "Live data unavailable" and the existing SBB link below it is the fallback.

API + CORS notes

  • GET https://transport.opendata.ch/v1/connections?from=&to=&date=&limit=4 — outbound
  • GET https://transport.opendata.ch/v1/connections?…&time=21:00&isArrivalTime=1&limit=6 — return, anchored to arrive home by 21:00
  • Server sends Access-Control-Allow-Origin: * — works under file://, http://, https://.
  • Uses XMLHttpRequest (not fetch) per project file://-safe convention.
  • SBB has no public iframe widget — only the link parameters (?von=…&nach=…) that are already used for the static fallback button.

Recommendations

  • "From" defaults — three-tier: (a) localStorage["hike-transit:origin"], (b) per-deployment window.HIKING_CONFIG.defaultOrigin, (c) hardcoded "Zürich HB". Skip IP geolocation — CORS/privacy headache for marginal benefit; the inline input is two clicks.
  • "Drive there with traffic"? Out of scope. Existing "Google Maps (driving)" link already passes ttype=arr&date=… — let Google handle traffic. Distance Matrix API for inline ETAs would need a paid Google key.

Open follow-ups

  • Gate behind opt-in? Widget propagated to all 75 hikes. Could pilot on Augstmatthorn first via a data.json field like getting_there.live_transit: true.
  • Non-station trailheads. Some hikes have trailhead.name values that aren't recognised SBB stations (e.g. "parking lot"). API returns no connections, widget shows "no more today". Cheap fix: detect empty /locations response and show "couldn't find station".
