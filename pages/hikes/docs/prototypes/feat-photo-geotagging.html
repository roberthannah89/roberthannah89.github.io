Photo Geotagging

Clustered photo thumbnails pinned on the route map at exact EXIF GPS points — pipeline live, blocked on EXIF-bearing source photos.

BLOCKED-ish

Demo

Open augstmatthorn.html — 12 photos render as 8 pins (5 singletons + 3 clusters with badges 3 / 2 / 2)

Click a cluster → popup with main image + thumbnail strip; click a thumbnail → main image swaps. The 12 marker positions are synthetic (distributed along the GPX) since no SAC photo has EXIF GPS today.

The real finding — no hike has EXIF GPS today

0% of current hike photos have real EXIF GPS. Every photo in the repo is a SAC image served from www.sac-cas.ch/.../csm_… URLs — SAC's image processor strips all EXIF metadata. Pillow reports 0 EXIF tags on every sample.

The feature pipeline is fully built and the rendering works. It only becomes real once you start adding your own local photos with intact EXIF GPS to routes/<slug>/local-photos/.

What got built

  • scripts/extract_photo_coords.py — production extractor. Reads JPG/PNG/HEIC from local-photos/, pulls GPSLatitude / GPSLongitude / GPSAltitude / DateTimeOriginal via Pillow, writes photo_coords.json next to the photos. Skips photos without GPS and reports the count. Validated on a real EXIF set: 2 with GPS + 1 without → correctly extracted 2, skipped 1.
  • scripts/prototype/synthesize_photo_coords.py — prototype helper that distributes existing SAC photo URLs along the GPX. Output is clearly marked "source": "synthetic-prototype" in _meta.
  • Render pipeline (render_hike.py) opportunistically loads photo_coords.json if present — no opt-in needed.
  • Template emits window.PHOTO_COORDS; hike_page.js has setupPhotoMarkers with screen-distance clustering and click-to-enlarge popups.

How to use

python scripts/extract_photo_coords.py --slug augstmatthorn
# or for one-offs:
python scripts/extract_photo_coords.py --photo-dir <dir> --out <coords.json>
make render

Open questions — resolved

  • Fallback for photos without EXIF GPS — build a timestamp-on-track interpolator. GPX has per-point timestamps; DateTimeOriginal usually survives even when GPS doesn't. Requires GPX + camera clock in same timezone. Defer to a future iteration.
  • Privacy / EXIF stripping — once we serve photos from our own domain, yes, strip. The map already discloses location, but raw EXIF leaks camera serial, "home" address (phone first-taken-at-home), exact moment. Add --strip-exif-on-export to whatever script copies photos into the published dir; keep originals outside the repo.
  • Batch rollout — pipeline supports it today; nothing to roll out until local photos exist. Per-hike-after-the-hike: add photos to routes/<slug>/local-photos/, run extractor, make render. A wrapper make extract-photos slug=<slug> would be a tiny follow-up.
