QR Code on Hike Pages

QR badge in the hero header encoding the page URL — fast hand-off from desktop to phone in the field.

DONE

Demo

Open augstmatthorn.html in worktree

QR ships on all 75 hikes via the shared template, not just the demo hike. Visible top-right on the hero photo, auto-hidden <700 px and in @media print.

What got built

  • Top-right card on the hero header (124 px wide, 108×108 px QR + caption "Scan to open on phone").
  • QR is rendered as SVG — stays crisp at any zoom.
  • Encoded URL comes from the page's <link rel="canonical"> tag, with location.href as a runtime fallback.
  • Generated client-side, no network call — works fully offline.

Library choice

qrcode-generator @ 1.4.4 by Kazuhiko Arase (MIT). Vendored locally at templates/_assets/qrcode.min.js — 20.7 KB minified (~6 KB gzipped).

Picked because it's pure JS (no <canvas> / Web-Worker dependency), exposes a clean qrcode(...).addData().make().createSvgTag() API, and emits SVG. Leaner options (qr-creator ~7 KB) drop SVG output or require a build step — not worth the saved bytes once gzipped.

Files touched (in worktree)

  • templates/hike_page.j2.html — canonical <link>, hero <aside class="hero-qr">, vendored script + wrapper
  • templates/_assets/hike_page.css — .hero-qr styles + responsive/print hides
  • templates/_assets/qrcode.min.js — new (vendored)
  • routes/_assets/qrcode.min.js + all 75 routes/*/*.html — regenerated by make render

Open question — the publish URL

The canonical link currently uses the placeholder host hikes.example i.e. https://hikes.example/<slug>/. Two follow-ups needed before this is real:

  1. Pick the real publish domain — one-line edit in templates/hike_page.j2.html.
  2. Confirm the URL convention — <host>/<slug>/ vs <host>/routes/<slug>/ vs something else.

The file:// fallback (read location.href when no canonical resolves) is intentionally only a debugging convenience — phones can't navigate to a desktop file URL.
