# CC ↔ Hikes-index engine unification — design

**Status:** Approved 2026-07-05. Follow-on to [`2026-06-28-hikes-page-harmonization-design.md`](2026-06-28-hikes-page-harmonization-design.md) (Phases 1, 2, 3, 5 shipped; Phase 4 deferred and rolled into this spec's Phase H).

## Goal

Finish converging Command Center (`pages/hikes/command-center/`) and the hikes index (`pages/hikes/index.j2.html` + `templates/_assets/index_page.js`) onto a single shared engine. After this work:

- One implementation of every shared feature (markers, clusters, side panel, day picker, filter matcher, URL sync, weather lookup, webcam layer, avalanche layer). No `// matches command-center.js` comments anywhere.
- Pages differ only in **which** shared modules they instantiate, **which container** those modules render into, and **which config args** they pass. Turning a feature on/off = the page either calls `Module.mount()` or doesn't.
- The shipped 2026-06-28 harmonization's data flows (pre-baked WEATHER_CACHE, shared webcam/SLF layers, marker-pill CSS) stay as-is — this spec extends them.

## Non-goals

- Merging the two pages into one URL. They remain two distinct entry points.
- Retiring the index's card grid or region/canton filters (both stay page-specific).
- Rewriting the SAC pipeline, `make render`, or any data-fetching script.
- Mobile / offline / PWA finish work. Explicitly deferred; parked in [`docs/TODOS.md`](../../TODOS.md) under "Mobile / offline (PWA finish work)".
- Introducing a bundler, ES modules, or `<script type="module">`. Pages open via `file://` in dev; everything stays IIFE + `window.*` globals + `<script src>`.

## Architecture

### File layout

Everything shared moves to a new `templates/_assets/hike_map/` directory. Every module attaches a factory or namespace to `window.HikeMap.*`.

```
templates/_assets/hike_map/
├── DESIGN.md             # sole source of truth for engine behavior
├── grade_colors.js       # window.HikeMap.GRADE_COLORS + gradeColor(g)
├── marker_factory.js     # window.HikeMap.MarkerFactory({...})
├── cluster_group.js      # window.HikeMap.ClusterGroupFactory({...}) + SKY_TINTS
├── wx_lookup.js          # window.HikeMap.WxLookup({fuzzy})
├── day_picker.js         # window.HikeMap.DayPicker.mount({container, ...})
├── side_panel.js         # window.HikeMap.SidePanel.mount({...}) (moved from command-center/)
├── side_panel.css        # theme-coupled CSS extracted from command-center.css
├── filter_store.js       # window.HikeMap.FilterStore({keys, initial})
├── filter_matcher.js     # window.HikeMap.FilterMatcher.factory({wxLookup})
├── filter_bar.js         # window.HikeMap.FilterBar.mount({container, store, filters})
├── url_sync.js           # window.HikeMap.UrlSync.bind({store}) + canonical key map
├── weather.js            # MOVED from command-center/weather.js
├── weather-cache.js      # MOVED (data, regenerated by `make weather`)
├── webcams.js            # MOVED
├── webcams_windy_data.js # MOVED (data)
├── slf_layer.js          # MOVED + renamed (was slf-layer.js)
├── slf_cache.js          # MOVED + renamed (was slf-cache.js)
└── marker_pill.css       # MOVED from templates/_assets/marker-pill.css
```

**`command-center/` after the refactor:** `index.html`, `command-center.js` (thin composition), `command-center.css` (page-specific chrome only), `DESIGN.md` (page-specific).

**`templates/_assets/` after the refactor:** map_shared.js/.css, hike_page.js/.css, hike_popup.js/.css, swiss_border.js, hike_3d.js, transit_widget.js, sw-register.js, index_page.js (thin composition).

### Feature on/off works by non-instantiation

There are no boolean feature flags. Every "flag" is either:
- A config arg to a factory (`MarkerFactory({ showHasPage: false })`), or
- A decision by the page not to call `mount()` at all (index page doesn't `FilterBar.mount()` because its filters render as external buttons above the card grid).

This keeps runtime cheap (no flag lookups on hot paths), keeps the config surface small (only args each module actually needs), and makes "what's on this page?" answerable by grepping the page's composition script for `HikeMap.*` calls.

### Module APIs

```js
// grade_colors.js
window.HikeMap.GRADE_COLORS = { 1:'#5cbf6a', 2:'#5cbf6a', 3:'#e8a832', 4:'#d97333', 5:'#cc3333', 6:'#8844cc' };
window.HikeMap.gradeColor = (grade) => /* 'T3' -> '#e8a832' */;

// wx_lookup.js — wraps WeatherService with optional fuzzy fallback.
window.HikeMap.WxLookup = ({ fuzzy = false } = {}) => ({
  get(latOrPoi, lonMaybe, dayIndex),   // exact; if fuzzy, fall back to nearest ≤ ~1 km
  freezingLevel(lat, lon, dayIndex),
});

// marker_factory.js
window.HikeMap.MarkerFactory = ({
  wxLookup,
  showHasPage = false,   // CC true (some POIs lack pages), index false (all have pages)
  showFreezing = true,   // ❄ pip when peak > forecast snow line
  gradeColors = window.HikeMap.GRADE_COLORS,
}) => ({
  makeIcon(poi, dayIndex),   // L.divIcon — pill if wx, dot otherwise; adds ★/❄ per config
});

// cluster_group.js
window.HikeMap.SKY_TINTS = { clear: {...}, 'partly-cloudy': {...}, cloudy: {...}, rain: {...}, snow: {...}, storm: {...} };
window.HikeMap.ClusterGroupFactory = ({ wxLookup, skyTints = window.HikeMap.SKY_TINTS, dayIndexGetter }) =>
  L.markerClusterGroup({ /* count + dominant emoji + avg temp pill */ });

// day_picker.js
window.HikeMap.DayPicker = {
  mount({ container, initial = 0, onChange })
  // returns { setActive(i), destroy() }; picks reads from WeatherService.getDayChoices()
};

// filter_store.js
window.HikeMap.FilterStore = ({ keys, initial = {} }) => ({
  get(k), set(k, v), setAll(partial), state(),
  subscribe(fn),   // fn(state, changedKeys)
  unsubscribe(fn),
  // Accepts unknown keys into state so cross-page URL hashes still apply via the matcher.
});

// filter_matcher.js
window.HikeMap.FilterMatcher = {
  factory({ wxLookup }) => ({
    match(matchablePoi, state),   // boolean; handles all known filter keys
  }),
};

// filter_bar.js
window.HikeMap.FilterBar = {
  mount({ container, store, filters, daySlotId = 'hm-day-slot' })
  // filters: e.g. ['grade','tm','el','gn','d','sk','t','sn','h','u']
  // Renders only the listed groups. Provides <div id={daySlotId}> for DayPicker to mount into.
};

// url_sync.js
window.HikeMap.UrlSync = {
  KEYS,                         // canonical short-key map (see § Canonical URL keys below)
  readFromUrl(),                // -> state object
  bind({ store }),              // two-way sync store <-> location.hash; does NOT fire on initial read
  reset(),                      // clear hash + reload
  copyLink(el, label='Copied'), // copy location.href, flash label
};

// side_panel.js (moved)
window.HikeMap.SidePanel = {
  mount({ container, wxLookup, dataAdapter, matchingHike, store })
  // dataAdapter: page-native -> matchablePoi/POI. matchingHike: (poi) -> optional local hike-page href.
  // Subscribes to store: day/filter changes re-render panel cards live.
  // returns { open(pageNative), close(), refresh() }
};

// webcams.js, slf_layer.js
window.HikeMap.WebcamLayer   = { create({ map }) };
window.HikeMap.AvalancheLayer = { create({ map }) };
```

### The matchablePoi contract

The shared matcher operates on a normalized POI shape. Each page produces it once at init from its native data.

```js
{
  name, lat, lon,
  grade: 'T3',           // best/highest grade if multiple routes
  region, canton, routeType,
  alt,                   // summit / peak altitude, metres
  gain,                  // vertical ascent, metres
  timeH,                 // hours, numeric
  hasPage: true|false,   // built page in this repo?
  poiKind: 'hike'|'hut', // for showHikes/showHuts filter (CC)
  raw: <original>,       // page-native ref, used by adapters/popups
}
```

Adapters live in each page (~15 lines each), not in the engine:

- Index: HIKES → matchablePoi (fields already align; `hasPage: true`, `poiKind: 'hike'` constants).
- CC: SAC POI → matchablePoi (flatten `routes[]` to best grade; compute `hasPage` from `SidePanel.matchingHike`).

### Composition sketch — CC

```js
const wx = HikeMap.WxLookup({ fuzzy: false });
const markerFactory  = HikeMap.MarkerFactory({ wxLookup: wx, showHasPage: true, showFreezing: true });
const clusterGroup   = HikeMap.ClusterGroupFactory({ wxLookup: wx, dayIndexGetter: () => store.get('d') });
const store          = HikeMap.FilterStore({
  keys: ['g','tm','el','gn','d','sk','t','sn','h','u','wc','av'],
  initial: HikeMap.UrlSync.readFromUrl(),

const matcher = HikeMap.FilterMatcher.factory({ wxLookup: wx });

HikeMap.UrlSync.bind({ store });
HikeMap.FilterBar.mount({ container: '#cc-filter-bar', store, filters: ['g','tm','el','gn','d','sk','t','sn','h','u'] });
HikeMap.DayPicker.mount({ container: '#hm-day-slot', initial: store.get('d') ?? 0, onChange: i => store.set('d', i) });
HikeMap.SidePanel.mount({ container: '#cc-side-panel', wxLookup: wx, dataAdapter: sacPoiToMatchable, matchingHike: findBuiltHike, store });
HikeMap.WebcamLayer.create({ map });
HikeMap.AvalancheLayer.create({ map });

// Marker loop: markerFactory.makeIcon(poi, store.get('d')); matcher.match(poi, store.state()); …
```

### Canonical URL keys

One table, in `hike_map/url_sync.js`. Both pages use the same short keys — a hash minted anywhere applies anywhere via the shared matcher.

| Key | Short | Type | CC UI | Index UI | Matcher applies |
|---|---|---|---|---|---|
| grade | `g` | multi-select `T1,T3,T5` | ✅ | ✅ | ✅ |
| region | `r` | multi-select | — | ✅ external | ✅ |
| canton | `c` | multi-select | — | ✅ external | ✅ |
| route_type | `rt` | multi-select | — | ✅ external | ✅ |
| distance | `di` | bucket | — | ✅ | ✅ |
| time | `tm` | bucket ≤3h / 3-5h / 5h+ | ✅ (was `dur`) | ✅ | ✅ |
| elev (peak alt) | `el` | bucket | ✅ | ✅ | ✅ |
| gain | `gn` | bucket | ✅ | ✅ | ✅ |
| day (forecast idx) | `d` | int 0–4 | ✅ | ✅ | drives wx display |
| sky (threshold) | `sk` | "or better" ordinal | ✅ | — | ✅ |
| tempMin | `t` | number | ✅ | — | ✅ |
| season | `sn` | bool | ✅ | — | ✅ |
| showHikes | `h` | bool | ✅ | — | ✅ |
| showHuts | `u` | bool | ✅ | — | ✅ (no huts on index anyway) |
| webcams | `wc` | bool | ✅ toggle | ✅ toggle | not a filter |
| avalanche | *(none — superseded 2026-07)* | — | always on, no toggle | always on, no toggle | not a filter |

**Breaking rename:** CC's `dur` → `tm`. Old CC hash bookmarks stop resolving. Acceptable on a personal site.

### Cross-page URL semantics

`FilterStore` accepts unknown keys into `state()`. So a CC URL `#g=T3&sk=rain&t=10` pasted onto index:
- Index UI has no sky/temp controls.
- The matcher still applies `sk=rain` and `t=10`, so cards + markers filter.
- A **"Cross-page filters"** banner appears above the map noting that some filters have no UI on this page, with a **Clear** button that removes only the invisible keys.

This is a small UX add on both pages, mounted by `url_sync.js` (or a helper alongside it).

### Init order (per page, matters)

1. Read hash → `initial = UrlSync.readFromUrl()`
2. Build store: `store = FilterStore({ keys, initial })`
3. Construct factories: `wx`, `markerFactory`, `clusterGroup`, `matcher = FilterMatcher.factory({ wxLookup: wx })`
4. Mount UI: `DayPicker.mount(...)`, `FilterBar.mount(...)` (CC), external region/canton buttons wired to store (index)
5. `SidePanel.mount({ store, ... })` — subscribes for live refresh
6. Create markers, add to cluster group, add to map. Define `applyVisibility(state)` closure using `matcher.match`.
7. `store.subscribe((state) => { applyVisibility(state); refreshMarkerIcons(state.d); })`
8. `UrlSync.bind({ store })` — starts writing hash on subsequent `store.set` calls; must NOT fire during step 1's read.

## Risks and open questions

1. **Side panel CSS extraction (phase H) is the biggest single diff.** ~120 lines of theme-coupled CSS with many selectors. Mitigation: extract to CSS variables and set them on CC identically to today's values. Pixel-diff CC screenshots before/after. If a regression sneaks in, it lands here.

2. **`dur` → `tm` rename** breaks any existing CC hash bookmark. Personal site, no external contract — accept. Add a one-line shim in `url_sync.js` that translates `dur` → `tm` on read for one release if we want a soft cutover (not planned).

3. **First-click popup regression guard.** Phase D must preserve the CC popup invariant (see [`CLAUDE.md`](../../../CLAUDE.md) "Command center marker popups"). The `FIRST-CLICK REGRESSION GUARD` comment must port over to `marker_factory.js` verbatim, and the CSS `.leaflet-tooltip-pane { pointer-events: none }` rule stays in `marker_pill.css`.

4. **Service worker cache invalidation on file moves (phase A).** `SW_VERSION` bumps automatically on `make render`, so shell cache invalidates cleanly. Runtime cache is versionless — old entries for moved paths become dead weight until eviction. Functional impact: none.

5. **Cross-page filters banner** is a small UX add mentioned in Section 3 but not part of any prior spec. Simple: check `state()` for keys not in the current page's UI list, render a banner if any, provide a Clear button. Belongs in phase F (with url_sync).

6. **What if a phase breaks something?** Each phase is small enough to revert independently. If phase F breaks, revert it and land phase G against pre-F code.
