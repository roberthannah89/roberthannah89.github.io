# Architecture

## System Overview

This is a **static site generator** for Swiss Alps hiking guides. It reads from `data.json` files and renders interactive Leaflet.js maps + styled HTML pages.

```
data.json (source)
    ↓
render_hike.py (Jinja2 templating)
    ↓
hike page HTML + index.html gallery
    ↓
GitHub Pages (static hosting)
```

## Key Concepts

### Data Flow

1. **Source:** `pages/hikes/routes/<slug>/<slug>.data.json`
   - Hand-authored YAML/JSON with hike metadata, photos, route description
   - Validated against `templates/hike_data.schema.json`

2. **Processing:** `scripts/render_hike.py`
   - Loads all `data.json` files
   - Loads GPX route data from `<slug>.gpx`
   - Renders Jinja2 templates:
     - `templates/hike_page.j2.html` → `pages/hikes/routes/<slug>/<slug>.html`
     - `templates/index.j2.html` → `pages/hikes/index.html` (gallery)
   - Syncs CSS/JS to `pages/hikes/routes/_assets/`

3. **Output:** Static HTML + CSS/JS
   - Leaflet.js maps embedded in each hike page
   - Gallery with filters, weather strips, map overlay

### Map Architecture

- **Map library:** Leaflet.js 1.9.4
- **Basemap:** OpenStreetMap (Mapnik tiles)
- **Route overlay:** Generated from GPX file → `track.js`
- **Canton overlay:** Geojson layers with SAC grade coloring
- **Weather API:** Open-Meteo (batch request for all hikes on page load)

### GPX Building

- **Data source:** OpenStreetMap via Overpass API
- **Elevation:** SwissTopo REST API
- **Algorithm:** See [hiking/ROUTING-ELEVATION.md](hiking/ROUTING-ELEVATION.md)
- **Output:** `<slug>.gpx` + `<slug>.track.js` (Leaflet-compatible)

### Templates & Assets

- **Source templates:** `templates/` (Jinja2 `.j2.html` files)
- **Generated output:** `pages/hikes/routes/<slug>/<slug>.html` (static HTML)
- **Shared assets:** `templates/_assets/` → `pages/hikes/routes/_assets/`
  - Synced on every render to ensure CSS/JS stay in sync across all hike pages

## Build Pipeline

### Local Development

```bash
make render              # Render all hikes (parallel, ~180ms)
make render slug=X      # Render only hike X
make validate           # Validate data only (no output written)
make serve port=8000    # Render then serve on localhost:8000
```

### CI/CD (GitHub Actions)

Triggered on push to `main`:

1. **Validate data:** `render_hike.py --validate-only`
2. **Check docs:** `check_hiking_docs.py` (verify CLI flags documented)
3. **Render:** `render_hike.py` (generate all pages)
4. **Deploy:** Push to `gh-pages` branch (GitHub Pages auto-deploys)

See [.github/workflows/pages.yml](../.github/workflows/pages.yml)

## File Roles

| File | Purpose | Edited By |
|------|---------|-----------|
| `<slug>.data.json` | **Source of truth** for hike metadata | Humans (directly or via `add_hike.py`) |
| `<slug>.gpx` | Route track | Generated by `build_hike_gpx.py` |
| `<slug>.track.js` | Leaflet-compatible map data | Generated by `render_hike.py` from GPX |
| `<slug>.html` | Generated page | Generated by `render_hike.py` |
| `index.html` | Generated gallery | Generated by `render_hike.py` |
| `_assets/*.css`, `_assets/*.js` | Shared styling & interactivity | Developers, synced from `templates/_assets/` |

## Dependencies

- **Python:** 3.12+
- **Libraries:**
  - `jinja2` — template rendering
  - `jsonschema` — data validation
  - `requests` — HTTP (for Overpass API, SwissTopo, image validation)
  - `PIL` — image optimization
  - `gpx` libraries (if using GPX parsing)

- **External APIs:**
  - **Overpass API** (OSM routing)
  - **SwissTopo REST API** (elevation data)
  - **Open-Meteo API** (weather forecast)
  - **MediaWiki API** (Wikimedia image validation)

See [requirements.txt](../requirements.txt) for exact versions.

## Agent Independence

All critical knowledge is stored in **docs/** (plain Markdown):
- No agent-specific config files needed
- `.github/copilot-instructions.md` is brief and links to `docs/`
- Any agent (Claude, Copilot, etc.) can read `docs/README.md` and understand the system
- Python docstrings are introspectable and provide additional context

## Performance

- **Render time:** ~180ms for 20 hikes (6.13× parallel speedup)
- **Validation time:** Instant (JSON schema checks)
- **Map load time:** <500ms per page (Leaflet + tile layers)
- **Weather API:** Batched request (1 API call for all hikes on page load)
